# DEC-008 — Build One Locked Ordinary-Argument Candidate Before Device Admission

- **Status:** Accepted
- **Scope:** WO-056 Phase L acceptance and Phase M ordinary-bootstrap candidate qualification
- **Finding:** Accept Phase L Outcome C as a correct pre-launch stop and authorize one build-only candidate whose locked iOS launch tuple removes `-gl4es_texture_array_selftest` while preserving the self-test implementation as dormant, explicitly gated regression machinery. Device admission remains a separate later decision.

## Why it matters

Bundle 124 cannot test the first unqualified production boundary because its disabled launch field deterministically selects the already-qualified diagnostic harness. The source graph and direct code show that `IOS_LaunchDialog` supplies the arguments consumed by `IOS_GetArgs` and then `Host_Main`; therefore the mismatch can be corrected without changing the Phase K renderer or Diffusion implementation. Separating candidate construction from device acceptance preserves the project's observation → bounded implementation → build qualification → device evidence sequence.

## Evidence

- WO-056 Phase L Outcome C commit `c7be0a237ad223e60b7808a903d2411a9154c153` records that Bundle 124 was not installed or launched and its one-run authorization remains unconsumed.
- `engine/platform/ios/launchdialog.m` assigns the combined diagnostic tuple to the only launch field, disables the field, and derives `argv` from its text.
- `engine/common/launcher.c` calls `IOS_LaunchDialog`, obtains `IOS_GetArgs`, and passes that exact `argc/argv` to `Host_Main`.
- Existing validators and `verify_ipa.sh` currently require the combined diagnostic launch string, so truthful candidate qualification requires coordinated validation and exact packaged-string discrimination rather than a one-line unverified source edit.
- [WO-056](../WorkOrders/WO-056.md) and [evidence manifest](../Evidence/WO-056/manifest.md).

## What this does not establish

This decision does not device-accept a future candidate, consume the Phase L launch authorization, or prove live provider/engine/Diffusion agreement. It does not qualify landscape loading, terrain shader execution, drawing, transitions, gameplay, or `ch1map1`. It does not authorize restoration of editable launcher settings or removal of the diagnostic harness.

None. This implements the smallest next step exposed by DEC-007 and Phase L Outcome C while preserving DEC-006's conditional production-admission contract.
